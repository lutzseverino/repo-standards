# Project documentation discovery

Identify independently maintained projects from positive ownership and build or
deployment evidence. A project can require documentation when its directory has
no README. A familiar filename by itself does not establish membership.

For every candidate, explain inclusion or exclusion. Treat test fixtures,
generated output, archived copies, and directories that only group teams or
projects as candidates requiring evidence, not maintained projects by default.
Leave uncertain maintenance or ownership as an unresolved question.

For each included project, plan individual files for its project README, every
existing documentation source that will move, each destination and introduced
documentation index, and every file whose links need repair. Do not include
`docs/catalog.json`; the source owns that exact file. An explained empty list is
valid when evidence shows that no maintained project is present.
